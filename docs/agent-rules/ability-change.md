# ability_change — правила блока замены способностей

Правила для `ability_change(old, new)` — визуального 2-панельного блока замены/реворка способностей.

## Когда использовать

- Способность заменяется другой (разные имена) — `ability_change(old, new)`
- Innate reworked — ВСЕГДА `ability_change`, никогда не два плоских `t("MISC")`. Генератор (`tools/generate_patch_code_v2.py`) пишет `# TODO[innate-swap]:` / `# v2-todo:` — никогда не оставлять в коммите.
- «Innate ability reworked» в патчноуте: лифтить OLD desc из патча, который вводил текущий innate (`hero_innate_<entity>_<ability>` в `patchnotes_english.txt`). **Никогда не придумывать** — спросить у пользователя, если KV-текст не найден.

## Unified layout (обязателен для всех блоков)

Каждый `ability_change` в 7.41+ использует `summary` + `tag`:

| Ситуация | summary | tag |
|---|---|---|
| old.name ≠ new.name, innate | `"New innate ability."` | `"new"` |
| old.name ≠ new.name, не innate | `"New ability."` | `"new"` |
| old.name == new.name, innate | `"Innate reworked."` | `"rework"` |
| old.name == new.name, не innate | `"Ability reworked."` | `"rework"` |

**Никогда** не писать `"New innate ability replacing X."` или `"<AbilityName> reworked."` — заголовок уже показывает оба имени.

## Layout-режимы

1. **`is-in-place`** — `old.name == new.name` И иконки совпадают. Правая шапка скрывается (показывается только левая). Одна шапка — всегда, когда имя+иконка одинаковые.
   - Sub-mode **`is-new-taller`** — если `new_rows > old_rows`: новая панель `align-self: start`, без лишнего padding-top. Контент плотно к верху.
2. **`compact-old` / `compact-new`** — разная identity И разница строк ≥ 2. Меньшая панель центрируется.
3. **Plain symmetric** — всё остальное.

## Две стороны Arc Warden — `two_selves_change`

С 7.33 по 7.37e у героя и Tempest Double были разные значения способностей: сначала по стороне карты, с 7.36 по фасету (Order у каждого своё, Disorder поменялись). В 7.38 значения общие. Карточка (владелец 2026-11-05): слева описание игры и две строки со значками героя и клона, справа описание и одна строка с двумя значками, тег REWORK. Проценты не ставим: у героя и клона они разные. Генератор `_postprocess_two_selves_cards` собирает её из «Previous values» заметки Valve.

## Сначала строки, потом карточка — `rows_first`

Владелец 2026-11-05 (Arc Warden 7.38): все строки способности с тегами стоят вместе под её названием, ниже подпись и карточка:
`ability_change(..., rows_first=lambda: [li(...), li(...)])`. Функция, а не список: строка делается после карточки, когда та уже
задала способность и значения. Строка с собственной карточкой («Added Aghanim's Scepter») остаётся под главной карточкой. С 2026-11-05 так на
всех страницах (50 карточек, генератор `_postprocess_rows_first`); не тронуты списки с чем-то кроме строк (7.37: переменная
`scale_pill` в списке) и списки только из строк Aghanim со своими карточками.

## Значения таблицей — `patch/value_tables.py`

Владелец 2026-11-05: в любой карточке три значения и больше («Speed: 1600. Distance: 1200. …») стоят таблицей на всю ширину:
название | значение по центру, линии между ячейками. Значение — число или формула; фраза («Grants this ability: …») остаётся
текстом. Таблица уровней формулы открывается под своей строкой. Делается при сохранении страницы, для всех видов карточек.
У строки Aghanim в карточке синий — полоса сверху, гаснет вниз («иначе всё синее»).

Владелец 2026-11-06:
- Таблица без своей рамки: доходит до краёв карточки, сверху одна линия (рамка в рамке смотрелась двумя линиями). Так же
  таблица Arc Warden «два себя» (`.selves-table`).
- Когда значений на таблицу хватает, ни одно не встаёт в скобки в фразу (`_aghs_inline`): 7.41 Objurgation «barrier
  (120/180/240/300)» стоял в тексте рядом с таблицей остальных.
- Формула, которую уже открывает строка над карточкой того же блока, в карточке — простой текст, без второй кнопки и
  таблицы (`drop_formulas_said_above`, 7.41 Persecutor).
- Улучшение Aghanim пишет значение с улучшением, а не прибавку: «Increases Max Mana Burned per Hit to 3.1/3.9/4.7/5.5%»,
  в таблице «Radius | 700» (`aghs_text._total`: «+» складывает, «=» ставит, «x» умножает, «-50%» — доля). Прибавка
  остаётся, только если основу не сложить (значение растёт с уровнем героя). Процент — по подписи «%» или по
  `display_type` «…Percentage» (Mana Break писал «+1.5» без %). Сравнение двух патчей идёт по прибавкам
  (`totals=False`), чтобы смена основы не выглядела переделкой улучшения.
- Руны в любой строке карточки (и в строках Aghanim) — одни значки, имя при наведении: «Level 3 - [i], [i], [i]»,
  «gains the [i] buff», «[i] or [i]» (`rune_name_chips`; «and» → запятая, «or» остаётся).
- Прибавка, которую фраза уже называет: «Decreases cooldown to 70/60/50s (by 10s)». Если после «by N» идут ещё слова
  («by 5 per win», 7.41 Duel), итог не вставляется — он не ложится на слово.
- Число, вставленное в скобки на одной стороне, уходит в таблицу, если таблицу строит другая сторона
  (`cards_aghs.INLINED` → `_lift_inlined`, 7.37 Flayed Flare).
- В карточке цветом выделяются только числа; фраза целиком не красится (`plain_phrases_in_cards`, 7.41 Muerta). Строки
  талантов вне карточек — как были.
- Две новые карточки подряд (без своих видимых строк) стоят парой, каждая на своей половине (`patch/card_pairs.py`,
  вариант D). Одиночная односторонняя карточка (с 2026-11-10) — как все: текст слева, карточка значений справа
  (`card_deck._solo`, `.vt-side`); справа от блока с линией она больше не стоит.
- Карточка значений называет КАЖДОЕ число текста (`patch/deck_extra.enrich` → `patch/deck_text.free_rows`). Порядок
  имён: словарь подписей `data/rules/value_names.json` (ключ — 6 слов до числа и 4 после, числа заменены на «#»;
  `""` — строки не надо) → имя из файлов игры → правила по фразе («every» → Interval, «for 4s» → Duration, «3x
  against creeps» → Multiplier against creeps, «increased by 0.66s» → «+0.66s»). Новый патч: `python
  tools/value_names.py missing` показывает числа без имени, вписать их в словарь. Пара «X (heroes)»/«X (creeps)» — одна
  строка, крипы мелко под героями (`merge_unit_pairs`). «(Scepter)/(Shard)» к имени — только если в карточке есть и
  строки самой способности. Последний проход — `patch/value_tidy.py`: у замедления знака нет, у «reduction» нет
  минуса, «by N» берёт знак глагола («reduces by 1s» → «−1s»), у времени есть «s» (или «min» по тексту), сокращения
  (Hp, Dps, Agi, pct) раскрыты, слова строчные (кроме имён, которые текст пишет с большой), «Scepter X» → «X
  (Scepter)»; плохие имена из файлов игры переименовывает `data/rules/value_labels.json`.
- Окраска в карточке значений — только то, что изменилось, и только против той же способности: новая способность
  (Tidebringer → Admiral's Rum) не сравнивается со старой, число «new» без старого значения не красится.
- Строка «Can be upgraded with Aghanim's Shard. …» под карточкой без своей части Shard уходит внутрь карточки её частью
  (`card_deck.retold_rows`). Переворот карточки «было/стало» — только по ярлыку, не по всей карточке.
- Таблица значений — от двух значений (`MIN_VALUES = 2`); во фразу Aghanim числа встают, пока их меньше трёх
  (`INLINE_UNTIL`).
- Строки карточки, каждая начинается значком способности (Overclocking, фасет на две способности), стоят как строки
  таблицы: линия над каждой, от края до края (`patch/card_sections.py`). У стороны без шапки, где значки разных
  способностей, у каждой строки своя шапка: значок, Active / Passive, имя (7.38 Power Capture) — той же полосой, что
  шапка карточки (`iab-head`). Строка «<b>Имя:</b> …», если сторона выше назвала «Имя ability», — описание
  подспособности: линия над ней (7.41 Zealot → Martyrdom).
- Обе стороны выданы одним улучшением (Overclocking: Scepter и в 7.40, и в 7.41) — шапки не пишут «granted by Scepter»,
  это говорит значок в строке «Ability reworked».
- Переименованная способность — одна способность: старого слага нет в новом патче, нового не было в старом, и у них
  не меньше 60% общих имён значений в файлах игры (`renamed`, `RENAME_SHARE`; Hawk → Raptors 94%, Boar → Razorback
  100%, Defense Matrix → Deploy Turrets 0%). Тогда один значок (без старого под ним) и % при наведении на новые числа.
- Что способность «scales with» — всегда в шапке (`_pane_scale`): фраза без точки в конце («Scales with Exorcism»), в
  скобках («(levels with Grow)»), «X depends on the level of Y:» (текст остаётся «X:»), а без слов — по формуле: «per
  minute of game time» → «scales with game time», «A + B per (hero) level» → «scales with level». «Scaling reworked» сам
  пишет каждой стороне, с чем она растёт.
- Строка REWORK «Aghanim's Scepter's X changed from … to …» скрыта, если текст улучшения у способности другой, чем в
  прошлом патче: карточка «было → стало» показывает оба (7.38 Holy Persuasion).
- Генератор: «Removed X ability» в General → блок способности X со строкой «Removed», если у героя в прошлом патче была
  такая способность, в том числе от улучшения (7.38 Blood Mist, Eject). Нет значка у удалённой способности — запустить
  `python scripts/fetch/fetch_icons.py`, затем `tools/make_thumbs.py`: CDN Valve (`dota_react/abilities/<slug>.png`)
  хранит и значки удалённых способностей (Eject, 2024-12), не только нынешних; «нет в файлах игры» — не повод
  оставлять без значка (владелец 2026-11-06).
- Убранный Aghanim — всегда коротко «Removed Aghanim's Shard.» / «Removed Aghanim's Scepter.».
- Строка Aghanim в карточке стоит у своей способности, с подсветкой скипетра/шарда и значком в конце строки; шапок
  «Aghanim's Scepter» / «Aghanim's Shard» над такими строками нет (владелец 2026-11-06, грани Invoker 7.38: «лишнее»;
  прежний вариант B с группами снят). «Can be upgraded with Aghanim's X.» в строке Aghanim не пишется — это говорят
  полоса и значок.
- Последнее слово строки, значки после него и [?] не разрываются переносом (`_glue_tail`): голый значок или [?] на
  новой строке нельзя.
- «Passive and active components.» → шапка «Active / Passive»; «Improves with game's time» → «scales with game time».
- Значки в шапке подняты на 1 px: цифры Radiance сидят выше середины строки (замер по пикселям).
- Генератор: строка REWORK «This results in …» / «This means …» дописывается к строке REWORK над ней
  (`_postprocess_rework_continuation`, 7.38 Jakiro).
- «Removed X ability» (генератор, `_postprocess_removed_facets`): имя способности берётся и из текстов игры прошлого
  патча (удалённых нет в нынешнем списке: Bad Juju, Parting Shot стояли в General). «X (Strength)» — часть способности
  X: строка уходит в её блок (Morphling). Скрытая подспособность (в игре `AbilityDraftPreAbility` родителя, Eject у
  Dismember), если у родителя уже «No longer upgraded with Aghanim's …», строки не получает.
- Грань без способности и без шапки — шапка «Passive» (Undulation, старая сторона Nyx); «Grants X ability» + «Passive.
  …» → шапка «Passive: X», строка «Grants …» уходит (Chicken Fingers). У `facet_change` нет блока «значок + имя», если
  полоса шапки уже его называет, и нет ужатой раскладки `is-in-place`.
- «Number of times +2 All Attributes can be skilled …» — всегда строкой под гранью, не в тексте карточки
  (`_facet_attr_rows`, как у Meepo); бейдж из «from A to B».
- Строки карточки с фоном бейджей (`acr-bg`) тоже получают шапки секций (Fleshfeast).
- Список способностей героя в строке («to Crystal Ball, Unicycle and Weighted Pie») — значок перед каждым именем
  (`ability_list_chips`), только если все имена — способности со значком.
- % при наведении: если старые числа не выделены, новое ищет старое по подписи («Minimum lifesteal: 12%»,
  `patch/number_tips.py`).
- Шапка карточки на компьютере не переносит значения на вторую строку: переносится «– scales/levels with …»
  внутри названия, значения стоят у первой строки (`align-items: flex-start`); на телефоне перенос значений разрешён.
  «Shares level with X» в шапке пишется короче: «levels with X».
- Строка Aghanim «… from A to B» скрыта, если карточка Aghanim ниже в том же блоке показывает A слева и B справа
  (`hide_rows_the_aghs_card_says`, 7.41f Fiend's Gate).
- Бейджи % у строки карточки с «from A to B» переходят на само число B: цвет, пунктир, % при наведении
  (`_badges_into_number`, 7.38 Fleshfeast, Undulation).
- Одна строка со значком способности среди других строк стороны — тоже секция с линией над ней (7.38 Morphling).
- Перечень способностей героя в строке — только значки, имена при наведении, «and» → запятая (как руны).
- Слово-значение игры («DISPEL TYPE: Basic Dispel») идёт в таблицу значений; подписи из заглавных букв пишутся
  обычно («Dispel type»).
- Шапка не повторяет перезарядку или ману, которые текст даёт формулой («Cooldown: 24.5 - 0.5 per level», Mischief).
- Карточки «было → стало» под строками способности: стороны по верхнему краю, каждая по своей высоте.
- Увеличенный значок подспособности растёт из центра и может закрыть часть текста (владелец 2026-11-06 откатил рост
  влево).
- Шапки секций («Passive: Feast») — только слова, без значков; значок со строки секции тоже уходит.
- Строка улучшения Aghanim в карточке способности уходит, если карточка Aghanim ниже в том же блоке показывает это
  улучшение (`drop_upgrade_rows_said_below`: 7.38 Nothl Projection, 7.40 Liquid Courage, Entangle, 7.41 Hunter in the
  Night, M.A.D., Tailwind).
- Сторона без короткого вступления длиннее 800 знаков сворачивается целиком и показывает 6 строк
  (`FOLD_WHOLE_CHARS`, `.acr-fold-whole`; Nothl Projection 947, Roshan's Throw 700 остаётся открытым).
- Сторону мерим по высоте, не только по знакам (владелец 2026-11-07, 7.38 Arcane Curse: «надо ещё судить … по высоте»):
  значения, которые станут таблицей, весят по 95 знаков за строку таблицы (`TABLE_ROW_CHARS`, `_side_weight`; строка
  таблицы ~28 px против строки текста ~21 px по ~70 знаков). Arcane Curse: текст 379 + 6 строк = 949 — текст открыт,
  таблица свёрнута. На всех патчах свёрнутых сторон стало 63 вместо 54.
- Стрелка карточки, у которой стороны стоят от одного верха, — на середине более низкой стороны, а не в пустоте рядом с
  высокой (владелец 2026-11-07, 7.38 Mirana Leap; `drawAbilityChangeConnectors`, раньше только у карточек Aghanim и по
  старой стороне).
- Талант, который только сменил уровень, не красится (красный — удалён, золотой — совсем новый); его [?] — по строке
  на талант, уровень и числа как «было → стало»: «Boulder Smash Damage: Level 20 → 15, +100 → +80 (−20%)»; новое
  значение зелёное, если талант стал лучше (уровень раньше, число больше), красное — если хуже, фиолетовое — если бонус
  другой; неизменные числа остаются в названии (владелец 2026-11-07, 7.38 Pangolier и Tiny; `change_line` в
  `patch/talent_marks.py`).
- Теги-плитки на всех патчах (`TAG_MARK_PAGES = None`, раскатаны 2026-11-07 после пробы на 7.41f и 7.38), вариант «Плитка 22x18» — см. «Десятый круг» ниже.
- Поиск: переход сразу, без прокрутки, найденный блок подсвечивается золотой рамкой ~2,5 с; ищутся и имена
  способностей в шапках карточек граней (Tree Dance).
- Пробные плитки: всё, что опиралось на колонку тегов 76 px (подсветка Aghanim, линейка, строки без текста), на
  этих страницах начинается от края строки, текст — после плитки (30 px).

  такое же расположение, как раньше теги стояли, только более компактно»): плитка 22×18 цвета тега с тёмным значком
  12 px на месте прежнего тега, текст с отступом 30 px, следующие строки под ним; только CSS, от 761 px (на телефоне
  теги словами). Ромбики и закладки строк на линии сняты (`li-lead-icon`, `--tm-gap`, `placeTagMark` удалены). Строка
  с точкой вместо тега — точка на месте плитки, текст на той же кромке. У карточек своих тегов нет, как раньше
  (владелец: «не ставь их тут, будут такие же положения, как раньше стояли теги» — `blockMarks` и всё, что ставило
  теги карточкам, удалено). Слово тега при наведении не выдвигается (владелец: «убери нововведение»). На линии

## Что внутри / снаружи блока

**Внутри `old.desc` / `new.desc`:** только официальное описание способности (как в игре / KV). Никакой отсебятины («Self-buff nerfed:», «Pre-7.41 …»). Включать полный stat summary: Duration, Damage, CD, Mana Cost.

**Снаружи** (после `W(ability_change(...))`): числовые изменения через `W(ul_open())` / `W(li(...))`. Это stat deltas, пережившие реворк.

**Inline-note к новой механике** → приклеивать `+ inline_note(...)` к той строке `new.desc`, которую она поясняет (отдельный элемент `desc=[..., inline_note(...)]` рисуется пустой строкой с одним «?»). Никогда не `W(subnote(...))` после блока — это рендерится ВНЕ карточки.

```python
# WRONG — subnote вне карточки
W(ability_change(old=..., new=dict(desc=["..."])))
W(subnote("Movement slow is 100% for 0.2s."))

# RIGHT — clarification внутри
W(ability_change(old=..., new=dict(
    desc=["... slows movement by 100% for 0.2s ..." + inline_note("Effects linger even if the enemy dies.")])))
W(ul_open())
W(li("Cooldown decreased from 45 to 40", b(45, 40, l=True)))
W(ul_close())
```

## Dedup в desc: что убирать

Внутри `ability_change` desc убирать фразы, которые уже видны из unified-заголовка или innate-маркера:

1. `"Innate. Passive."` → `"Passive."` (маркер уже показывает "innate")
2. `, can't be leveled up` → убрать полностью
3. `, improves with <HeroName>'s level` → убрать когда есть `scale_pill`
4. `(promoted from a regular ability)` / `(promoted from the Aghanim's ability)` → убрать
5. `(reworked from the previous <X>)` → убрать
6. Числовые дельты `"Mana Cost: 50 (was 115)"` → убрать из desc, добавить снаружи как `li(..., b(115, 50, l=True))`

**Выделять жирным** ключевые цифры/термины в desc для визуальной иерархии.

## Per-level formula внутри vs снаружи

- **Внутри** пане — `scale_pill(...)` → `(pill, table)`, pill в текст, table в `tables=[...]`. Compact `levels=[1,5,10,15,20,25,30]` (полная сетка не влезает в полу-ширину).
- **Снаружи** — только текстовый `li("...", t("BUFF"))`, без таблицы.

## OLD desc — источник и форматирование

OLD desc = финальное состояние способности до текущего патча (как реальный тултип). Источник: вводящий патч в `patchnotes_english.txt` + все последующие твики до этого патча. Убирать «Per 7.XX…» и исторические паравраты — только конечный tooltip.

## NEW desc — сохранять неизменённые компоненты

Workflow: **baseline − deltas**, не «написать из 7.41 KV». Всё что патч не удалил/не изменил — остаётся в NEW desc. Типичные упущения: Duration, Spell Lifesteal, пассивная компонента у passive+active способностей.

## Renamed ability + Aghanim's DEL

Когда `ability_change` переименовывает способность (old.name ≠ new.name), грепнуть:
```bash
grep "DOTA_Patch_<ver>_<hero>_<new_slug>" data/patchnotes_english.txt | grep -i "no longer upgraded with aghanim"
```
Если есть — добавить `W(li("No longer upgraded with Aghanim's Shard", t("DEL")))` в `ul` рядом с блоком.

## Slot displacement

Когда regular ability становится innate → другая ability занимает освободившийся слот → в `new.desc` этой способности явно написать:
```python
desc=["Active. Now occupying Inner Beast's old slot (Inner Beast moved to innate).", ...]
```

## Aghanim rows внутри ability_change

Для Aghanim в desc пане — использовать `aghs_line(text)` / `aghs_shard_line(text)` (возвращает full-width div со stripe). Обычный `ul.changes li.aghanim-scepter` auto-classifier не работает внутри swap-панели.

## Innate/facet субgruппа

Изменения innate и facet → всегда под `subgroup("Abilities")`, НИКОГДА под авто-категорией «Other» (первый ul после hero_header). Other — только для base-stat изменений.

**PURE ul** (только ability/facet/innate): `W(subgroup("Abilities"))` до `ul_open()`.
**MIXED ul** (base stats + removals): закрыть stats ul, потом `W(subgroup("Abilities"))` + новый ul.
